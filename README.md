# WaBridge

A self-hosted WhatsApp workspace: a team inbox, contacts, safe campaigns, automations, a Claude AI assistant and a REST API. It runs on top of the open-source **OpenWA** engine, which links a WhatsApp number by QR code (like WhatsApp Web), so **no Meta App ID or business verification is needed**. The official Meta Cloud API is an optional extra channel.

```
Browser ──► WaBridge (port 8080) ──► OpenWA engine (port 2785) ──► WhatsApp
                ▲                            │
                └──── signed events ◄────────┘
```

* **WaBridge** (this folder) provides the new UI/UX, users and roles, inbox, CRM, campaigns, automations, AI, webhooks and the public API.
* **OpenWA engine** (`rmyndharis/openwa` Docker image, MIT licence) holds the WhatsApp sessions. It is used unchanged, so you can update it any time.

> ⚠️ Linking a number this way is **unofficial** automation and always carries some ban risk. Use a dedicated number, warm it up slowly, and only message people who agreed to hear from you. For large marketing sends, use the official channel.

## 1. What you need (credentials and keys)

| What | Required? | Where it comes from | Where it goes |
|---|---|---|---|
| A phone with WhatsApp or WhatsApp Business, using a **dedicated number** | ✅ | Your SIM | Scan the QR in *WhatsApp numbers* |
| `OPENWA_API_KEY` | ✅ (auto) | Generated by `windows\setup.ps1` | `.env` |
| `WABRIDGE_SECRET` | ✅ (auto) | Generated by `windows\setup.ps1` | `.env` |
| `OPENWA_API_KEY_PEPPER` | ✅ (auto) | Generated by `windows\setup.ps1` | `.env` |
| Admin email and password | ✅ | You choose them on the first visit | WaBridge sign-up screen |
| Anthropic API key (`sk-ant-…`) | Optional, for AI replies | console.anthropic.com → API keys | *Automations & AI → AI assistant* or `ANTHROPIC_API_KEY` |
| Meta **Phone Number ID** | Optional, official channel | WhatsApp Manager → API setup | *Integrations → Official API* |
| Meta **WABA ID** | Optional | WhatsApp Manager → API setup | same |
| Meta **permanent access token** (System User) | Optional | Business Settings → System users → Generate token (`whatsapp_business_messaging`, `whatsapp_business_management`) | same |
| Meta **App secret** | Optional | developers.facebook.com → your App → Settings → Basic | same |
| Meta **Verify token** | Optional | Auto-generated by WaBridge | Paste into the Meta webhook settings |
| Public HTTPS URL (e.g. Cloudflare Tunnel) | Only for Meta webhooks | `cloudflared tunnel --url http://localhost:8080` | Meta webhook = `https://…/hooks/meta` |

Your **Meta Business ID alone is not enough** for the official API. You also need an App, a WABA, a phone number registered on the Cloud API, and a token. The QR-linked (unofficial) channel needs none of these.

## 2. Install on Windows (Docker Desktop, recommended)

1. Install or update **Docker Desktop** with the WSL 2 backend, then start it and wait for *Engine running*.
2. Unzip `WaBridge.zip`, for example to `C:\WaBridge`.
3. Double-click **`Start WaBridge.bat`**. It:
   * creates `.env` with random secrets,
   * downloads the OpenWA engine and builds WaBridge (first run: about 5 minutes, about 1 GB),
   * opens http://localhost:8080.
4. Create your admin account. You become the admin.
5. Go to **WhatsApp numbers → Add number**, give it a name, and scan the QR with the phone (WhatsApp → ⋮ → *Linked devices* → *Link a device*). You can also use **Use phone number** for an 8-character pairing code.
6. Done. Messages now arrive live in **Inbox**.

Daily use: `Start WaBridge.bat` / `Stop WaBridge.bat`. More commands:

```powershell
powershell -ExecutionPolicy Bypass -File windows\manage.ps1 logs      # live logs
powershell -ExecutionPolicy Bypass -File windows\manage.ps1 status    # container status
powershell -ExecutionPolicy Bypass -File windows\manage.ps1 backup    # backup to .\backups
powershell -ExecutionPolicy Bypass -File windows\manage.ps1 update    # newer engine (change OPENWA_VERSION in .env first)
powershell -ExecutionPolicy Bypass -File windows\manage.ps1 test      # end-to-end smoke test
```

**Laptop tips:** turn off sleep while plugged in (Settings → System → Power), and enable *Start Docker Desktop when you sign in*. Numbers reconnect automatically after a restart (`AUTO_START_SESSIONS`).

### Without Docker for WaBridge (Node.js 22.19+)

The engine still runs in Docker; only WaBridge runs from Node:

```powershell
docker compose up -d openwa
copy .env.example .env      # fill OPENWA_API_KEY etc., and uncomment the three "without Docker" lines
npm ci
npm run build
npm start                   # http://localhost:8080
```

In that case the engine has to reach WaBridge on your PC: set `WABRIDGE_PUBLIC_URL=http://host.docker.internal:8080` in `.env`, and add `host.docker.internal` to the engine's `SSRF_ALLOWED_HOSTS` in `docker-compose.yml`.

## 3. Test that everything works

1. **Health:** the top bar shows **Engine online** and **Live**.
2. **Link a number:** its card turns **Connected**.
3. **Inbound:** send a WhatsApp message *to* the linked number from another phone. It appears in **Inbox** instantly.
4. **Outbound:** reply from the inbox. Ticks go ✓ → ✓✓ → blue when read.
5. **Automations:** *Automations & AI → Add starter rules*, then message the number "price". The auto-reply arrives after a short, human-like delay.
6. **Simulator:** type any text in *Test your automations*. Nothing is sent.
7. **AI:** paste your Anthropic key, write a knowledge base, and use *Try it*.
8. **Campaign:** tag 2–3 friends who agreed, create a campaign, *Send test*, then start it.
9. **API:** *Integrations → API keys → Create*, then copy a curl example.
10. **Automated check:** `windows\manage.ps1 test` runs 22 end-to-end checks with no phone needed. It leaves two sample contacts tagged `smoke-test` and one *Smoke Tester* chat, which you can delete.

## 4. Features

**Engine features (all of OpenWA)**
* Multi-number sessions: QR or pairing code, proxy per number, start, stop, restart, unlink.
* Send text, image, video, audio, document, location and poll; receive everything; delivery and read status.
* Groups, channels, labels, status, catalog, profile and calls are all reachable from **Engine API explorer** or `/api/v1/engine/*`.

**Added by WaBridge**
* **Team inbox:** live updates, assign to teammates, open/pending/closed, internal notes, tags, quick replies (`/shortcut`), attachments, AI-drafted replies, history import (*Sync chats*), group chats.
* **Users and roles:** admin and agent logins, instead of sharing an API key.
* **Contacts CRM:** CSV import with column mapping, custom fields (`{{city}}`), tags, consent tracking, *on WhatsApp* check, export.
* **Safe campaigns:** a 5-step wizard with:
  * tag-based audiences and opt-in only (by default);
  * spintax `{Hi|Hello}` and variables, media, test send, scheduling;
  * random gaps, daily caps, quiet hours, and auto-pause after repeated failures;
  * a live progress view, retry failed, duplicate, and reply-rate tracking.
* **Automations:** welcome, keyword (contains/exact/starts/regex, Hindi/Hinglish friendly), away (business hours) and catch-all rules; cooldowns, priorities, auto-tagging, per-number rules, a simulator.
* **AI assistant (Claude):**
  * persona and knowledge base, hand-off keywords ("agent", "human"), per-chat rate limit;
  * human takeover: bots stay quiet after a person replies;
  * automatic model fallback on refusals.
* **Consent:** STOP/UNSUBSCRIBE (and START) handled automatically, and opted-out contacts are always skipped.
* **Warm-up guidance and daily limits per number,** plus the engine's own send pacing.
* **Official Meta Cloud API (optional):**
  * a second channel with approved-template campaigns;
  * an inbound webhook with signature check;
  * `channel: "auto"` API fallback when no linked number is online.
* **Integrations:** signed outgoing webhooks (message.received, message.sent, message.status, contact.opted_out, session.status, campaign.completed, …), API keys, a REST API.
* **Overview dashboard:** 14-day chart, delivery and read rates, median first-reply time, top automations, activity log, light and dark theme, mobile layout.

## 5. Public API (for your website, CRM or n8n)

Send the header `X-WaBridge-Key: wb_live_…` (create the key in *Integrations → API keys*).

| Method | Path | Body |
|---|---|---|
| POST | `/api/v1/messages` | `{ "to": "919876543210", "text": "Hi", "numberId?": "…", "channel?": "auto\|openwa\|meta", "media?": { "type": "image\|video\|audio\|document", "url" or "base64", "filename", "mimetype" } }` |
| POST | `/api/v1/messages/template` | `{ "to", "templateName" or "templateId", "variables": { … } }` |
| GET | `/api/v1/messages/:id` | Status of a sent message |
| POST | `/api/v1/contacts` | `{ "phone", "name", "email", "tags": [], "optedIn": true }` |
| GET | `/api/v1/numbers` | Linked numbers and their status |
| GET | `/api/v1/conversations?phone=` | Conversations for a phone |
| ANY | `/api/v1/engine/<path>` | Passthrough to the OpenWA engine `/api/<path>` |

Outgoing webhooks carry `X-WaBridge-Signature: sha256=<HMAC of raw body>`.

## 6. Website contact form → WaBridge (optional)

Your marketing site's contact form can create contacts in WaBridge, tagged `website-lead`, with the message saved in their notes:

1. Set `LEAD_FORM_ORIGINS=https://www.your-domain.com` in `.env` (your website's exact address), then restart.
2. Point the site's form at `https://<your WaBridge address>/api/public/leads`. WaBridge must be reachable over HTTPS; see the next section.

The endpoint stays switched off until an origin is listed. It accepts at most 10 kB per request and 5 leads per visitor every 10 minutes, and silently drops bots that fill the hidden spam-trap field.

## 7. Expose it to the internet (optional)

You only need this for Meta webhooks or remote access. Keep the dashboard private otherwise.

```powershell
winget install Cloudflare.cloudflared
cloudflared tunnel --url http://localhost:8080
```

Use the printed `https://….trycloudflare.com` URL. For a permanent domain, create a named tunnel and protect it with Cloudflare Access. Set `COOKIE_SECURE=true` when serving over HTTPS.

## 8. Troubleshooting

| Problem | Fix |
|---|---|
| **Engine offline** | `windows\manage.ps1 logs`. The first start takes 1–2 minutes. Check that Docker Desktop is running. |
| QR never appears | Restart the number. Make sure Docker has at least 2 GB of RAM (Docker Desktop → Settings → Resources). |
| Stuck at "Linking…" after scanning | Wait up to 2 minutes (WSL 2 is slow on the first link), then restart the number. |
| Phone asks to **create a passkey** and never links | A WhatsApp-side restriction on that account (OpenWA issue #560). Use another number, and don't reserve a WhatsApp username on the bot number. |
| A first message to a new contact never arrives | WhatsApp sometimes drops first contact (OpenWA issue #830). Ask customers to message you first, or use the official channel. |
| "Daily limit reached" / 429 | Your number's daily limit or engine warm-up pacing. Wait, or raise it carefully. |
| Messages not appearing in the inbox | *Settings → Engine* must show the event URL `http://wabridge:8080/hooks/openwa`. Restart the number to re-register it. |
| Forgot the admin password | Ask another admin to reset it in *Team*. Otherwise delete the `wabridge_wabridge-data` volume to start over. |

Data lives in two Docker volumes: `wabridge_wabridge-data` (WaBridge DB and media) and `wabridge_openwa-data` (WhatsApp logins). **Anyone with these can use your WhatsApp. Keep backups private.**
